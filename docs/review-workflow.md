# 复盘与技能更新工作流

> 目的：让 Claude 与用户每天对话中沉淀的可复用知识 / 技能，**可追溯地**回写本仓库；复盘只是触发器，技能改动经确认后才落盘。

## 每日轻复盘

**触发**：用户在当天对话中说"今日复盘"（手动触发，不设自动定时）。

**产出**：`reviews/daily/YYYY-MM-DD.md`，按 `_TEMPLATE.md` 模板，只记四件事：

1. 今日主题
2. 沉淀的可复用知识
3. 技能变更建议（新增 / 修改 / 删除 + 理由）
4. 遗留问题 / 待办

**落盘**：日提交到 GitHub（提交到 `main` 或由 PR 合并）+ 本地保留。

## 每周汇总

**触发**：每周日（或用户主动）。

**产出**：`reviews/weekly/YYYY-Www.md`，聚合本周 daily：

1. 本周主题与关键产出
2. **技能变更提案**：明确列出哪些技能要新增 / 修改 / 删除，含理由与证据
3. 待办跟进

**提交**：用户确认提案后，按以下流程落盘：

```
main 拉分支 → 上传/修改文件（skills/ 与 CHANGELOG.md）→ 提交推送 → API 创建 PR
```

每次技能变更在 `CHANGELOG.md` 记录：日期 / 改了什么 / 为什么（保证可回滚）。

## 技能库唯一归宿

所有 Claude 技能**只**放在 `skills/` 目录（按学术科研类 / 个人生产力类组织），不分散到其他仓库。具身智能系列门户仓库 `embodied-intelligence` 只做项目索引，不承载技能。

## 常见漂移检查点

- 实际安装的技能 vs `skills/` 目录是否一致（例：`weekend-trip-planner` 已安装但未回写仓库）。
- 新对话中产生的可复用方法论是否已沉淀为技能或文档。

## GitHub 操作注意事项

批量文件操作务必使用 Git Trees API 并传入 `base_tree`（否则会覆盖已有文件）；递归树提交时只提交 blob 条目。详见本项目历史教训。
